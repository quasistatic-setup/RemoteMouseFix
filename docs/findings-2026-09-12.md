# Findings of the Phase 1 measurement of 2026-09-12

Dated measurement report. It describes the state at the time of measurement and is meant
to be read as a historical record, not as a description of current behaviour. It was the
basis for the decision about Phase 2.

## Origin of the data

| | |
| --- | --- |
| Tool | RemoteMouseFix 0.1.0, Phase 1, observation only |
| System | Windows 10.0 build 26200, virtual screen 1920x1200, single monitor |
| DPI | `per-monitor-v2` in the tool, target window `dpi=120`, so 125 percent |
| Target process | `Wow.exe`, PID 6180, client `(320,75)-(1600,1099)`, so 1280x1024 physical |
| Mouse settings | `speed=10 threshold1=6 threshold2=10 acceleration=1` |
| Run A, local | `remotemousefix-20260912-201341_local.log`, 1897 events, 47 s |
| Run B, remote | `remotemousefix-20260912-201453_remote.log`, 471 events, 56 s |

Both sessions were terminated hard, so the footer is missing. The totals come from the
heartbeat lines. The data itself has no gaps, `dropped=0` in both runs.

The raw logs are kept outside Git. Log files are session data and are never versioned.

## How the measurement was run

Each run followed the same sequence, separated by markers: a click on a UI element as the
reference case, a single click into the 3D view without moving the mouse, a camera turn
with the right button held, and a drag with the left button held. Run A was done at the
machine with a physical mouse, run B through TeamViewer.

## Finding 1: WoW does not use ClipCursor, it uses a fixed warp anchor

Both runs report `clip=released` throughout. The pointer area is never restricted.

Instead, on a button press in the 3D view, WoW hides the cursor and moves it to a fixed,
window-relative anchor point:

```
## STATE cursor=HIDDEN | cursor_at=(804,554)     run A, client (320,75)
## STATE cursor=HIDDEN | cursor_at=(803,554)     run B, client (318,75)
```

The point is identical across all four drag phases of both runs and shifted by 1 px when
the window moved by 2 px. The anchor is therefore window-relative and fixed: client offset
`(484,479)` in run A and `(485,479)` in run B.

This matters for the method: the warp produces **no** WH_MOUSE_LL events, because
`SetCursorPos` does not pass through the low-level hook. It was visible only through the
state sampler. Without that sampler the central mechanism would have stayed invisible.

## Finding 2: the warp holds locally and never holds remotely

Only the phases with a hidden cursor were evaluated, that is, the actual camera turning.
Distance is `max(|dx|,|dy|)` from the anchor `(803,554)`:

| | Run A local | Run B remote |
| --- | --- | --- |
| Events within 3 px of the anchor | 58.3 % and 75.3 % | **0.0 %** |
| Median distance from the anchor | 3 px and 2 px | **163.5 px and 164.0 px** |
| Maximum distance | 123 px and 14 px | 396 px and 412 px |
| Events in the phase | 731 and 665 | 114 and 107 |

Locally the position alternates between `(804,554)` and `(805,554)`, so WoW keeps warping
it back. Remotely the cursor did not reach the anchor in a single one of 221 events.

## Finding 3: the click into the 3D view, isolated

The distance from the anchor at a button event is exactly the quantity WoW reads as the
camera delta. That makes this comparison the direct evidence:

| Run | Event pair | Offset on button down | Offset on button up |
| --- | --- | --- | --- |
| A local | left click in 3D | 123 px | **1 px** |
| A local | right drag | 123 px | **1 px** |
| A local | left drag | 123 px | **1 px** |
| B remote | left click in 3D | 259 px | **259 px** |
| B remote | right drag | 203 px | 145 px |
| B remote | left drag | 139 px | **412 px** |

The most telling single case, run B at `t=23.387`:

```
#000000136 LDOWN scr=(+00627,+00813) dt=1546ms flg=I-
## STATE cursor=HIDDEN | cursor_at=(803,554)
#000000137 MOVE  scr=(+00627,+00813) d=(+0000,+0000) dt=  63ms flg=I-
#000000138 LUP   scr=(+00627,+00813) d=(+0000,+0000) dt=   0ms flg=I-
## STATE cursor=SHOWN | cursor_at=(627,813)
```

Down and up are 76 ms apart and the mouse demonstrably did not move
(`d=(+0000,+0000)`). The sampler proves the warp to the anchor in between. The reported
position is still 259 px away from it. WoW therefore reads a camera delta of 259 px from a
click without any mouse movement.

The same event pair collapses to a 1 px residual distance locally.

## Finding 4: the remote stream is coarse and stalls periodically

| | Run A local | Run B remote |
| --- | --- | --- |
| MOVE events at comparable duration | 1888 | 460 |
| Step size median / mean | 2 px / 4.1 px | 5 px / 14.2 px |
| Step size p90 / maximum | 8 px / 122 px | 25 px / 429 px |
| Share of moves of 100 px or more | 0.2 % | 3.5 % |
| `dt` median / mean | 15 ms / 18.5 ms | 16 ms / 84.0 ms |

Within the drag phases, a pattern of pause and catch-up repeats remotely:

```
t=30.426 dt= 516ms d=( +89,-12)
t=31.204 dt= 531ms d=(+230,-43)
t=31.812 dt= 531ms d=(+125,-13)
t=32.554 dt= 516ms d=(-155,+23)
t=33.197 dt= 500ms d=(-203,+21)
```

About every half second the event stream stalls and resumes with a coarse absolute
position correction. The drag phases of run A show no such pattern. This amplifies the
effect from finding 2, but it is not its cause.

## Finding 5: injection markers

| | Run A local | Run B remote |
| --- | --- | --- |
| `LLMHF_INJECTED` | 0 of 1897 | **471 of 471** |
| `LLMHF_LOWER_IL_INJECTED` | 0 | 0 |
| `dwExtraInfo` | `0x0` throughout | `0x0` throughout |

Remotely, every event is therefore synthetic and absolutely positioned. TeamViewer sets
**no** signature in `dwExtraInfo`. Distinguishing remote from physical events is possible
only through `LLMHF_INJECTED`, not through `dwExtraInfo`.

## Conclusion

The working hypothesis is confirmed in substance and has to be corrected on one point: it
is not a cursor capture through `ClipCursor`, it is a warp to a fixed anchor.

The chain of effects:

1. WoW 3.3.5a implements relative mouse control through a repeated warp to a fixed anchor
   point and reads the cursor-to-anchor distance per frame as the camera delta.
2. TeamViewer continuously writes an absolute pointer position and undoes that warp within
   about 24 ms.
3. As a result the cursor sits 139 to 412 px away from the anchor instead of 1 to 3 px.
   That distance is exactly what is read as the camera delta. That is the jump.
4. In addition, the remote stream delivers roughly four times fewer positions and stalls
   every half second, so each individual update carries a much larger delta anyway.

Point 3 explains the core symptom completely, including the jump on a single click without
mouse movement. Point 4 explains the additional roughness while turning.

## Limits of this measurement

- **The tool's `RECENTER` heuristic never triggered**, `recenter=0` in both runs. It
  assumes the client centre `(640,512)` as the warp target, while the actual anchor is at
  client offset `(484,479)`. In that form the detection is ineffective. The finding was
  obtained from the `cursor=HIDDEN` state lines instead.
- **Why the anchor is not the client centre is open.** With `dpi=120` and a DPI-unaware
  game a scaling cause is plausible, but the measured offsets do not fit a single factor:
  `484/640 = 0.756` against `479/512 = 0.936`. A dedicated follow-up measurement would
  have to vary window size, the WoW resolution setting and the Windows scaling.
- There is only one repetition per case. The orders of magnitude are clear, the exact
  thresholds are not.
- Only one remote-control application and only one game version were tested.

## What follows from this for Phase 2

No decisions, only the constraints that follow from the data:

- The anchor has to be learned at runtime from the `cursor=HIDDEN` transitions, not
  calculated. After finding 1, any assumption about the client centre is wrong.
- Remote events are detectable only through `LLMHF_INJECTED`. `dwExtraInfo` carries no
  information.
- The warp itself is invisible in the hook stream. Any correction needs the state sampling
  as a second source of information.
- The periodic pauses of about 500 ms are a property of the transport, not of the game.
  They can be observed, but not removed by arithmetic.
